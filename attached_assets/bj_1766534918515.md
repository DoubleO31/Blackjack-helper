# Blackjack Helper App — Design (Electronic Blackjack, Las Vegas)

## 0) TL;DR
A mobile-friendly app that:
1) takes your hand + dealer upcard input and outputs the **optimal basic-strategy action** for the selected ruleset,
2) records **every hand + session P/L**,
3) lets you pick a **betting pattern** (bounded “spice”) and recommends the **next bet** after each outcome,
4) adds useful calculators (house edge, expected loss/hour, hands/hour pacing) and exports.

This targets **electronic/RNG blackjack**, where outcomes are generated via RNG with odds intended to match the underlying card model and where **house advantage comes from rules**.  :contentReference[oaicite:0]{index=0}

---

## 1) Goals and Non-Goals

### Goals
- **Fast in-casino workflow**: minimal taps per hand, big buttons, offline-first.
- **Correct action recommendations** using basic strategy for the exact rules.
- **Session tracking**: win/loss/push, blackjack, doubles, splits, surrender, bet size, running bankroll.
- **Bet advisor**: user-selected betting “pattern” with hard caps to avoid runaway progression.
- **Ruleset-aware house edge** estimator and “expected loss/hour” awareness.

### Non-Goals
- No card counting / shuffle tracking / advantage play that relies on deck composition (not useful for typical electronic/RNG games).
- No “beat the casino” claims; betting systems don’t change EV, but can change variance.

---

## 2) Game Types Supported
- **Single-player video blackjack**
- **Electronic table game (ETG)** blackjack (multi-seat terminals)

Assumption: each hand is dealt from a fresh or effectively random shoe (common for video blackjack), so basic strategy uses “infinite shoe” logic by default. (Optional: finite-deck mode for rule-accuracy if the machine clearly states decks and behavior.)

## 3) Ruleset Configuration (User-selectable)
The app starts with a **Rules Wizard** (save profiles per casino/machine):

- Decks: 1 / 2 / 4 / 6 / 8
- Dealer: **H17 vs S17**
- Blackjack payout: **3:2 / 6:5 / 1:1**
- Double: allowed? (any two / 9-11 / 10-11 / none)
- Double after split (DAS): yes/no
- Split: max hands, re-split aces yes/no
- Surrender: none / late
- Dealer peek for blackjack: yes/no (relevant if you model it)

### House Edge Module
- Primary: local house-edge estimator using the same engine used for strategy generation.
- Validation mode: compare against a known calculator for the same rules (useful in testing). Wizard of Odds provides a house edge calculator and rule-variation deltas you can use for sanity checks. :contentReference[oaicite:1]{index=1}

## 4) User Input Model (Fast “Card Feed”)

### Per hand, minimal input:
- Dealer upcard: A,2..10 (face cards treated as 10)
- Player hand:
  - Quick-entry: tap rank buttons (A,2..10)
  - Support soft/hard and pairs automatically derived
- Optional hand states:
  - “This hand is a split hand #k”
  - “I doubled”
  - “Surrendered”
  - “Blackjack”

### Outcome capture
After the hand resolves:
- Result: Win / Loss / Push / Blackjack Win / Insurance outcome (if user uses it; default discourage)
- Dealer final total (optional, for analytics)
- Notes: optional

### Undo / correction
- One-tap undo last action, because mis-taps happen in casino lighting.

## 5) Core Engine: Optimal Strategy

### Approach A (recommended): Generate strategy via EV recursion (offline, exact-to-rules)
Compute expected value for each action (Stand/Hit/Double/Split/Surrender) under the selected rules.

High-level:
- Represent cards as probabilities (infinite shoe) or finite shoe (optional).
- For each player state (hard total, soft total, pair, split depth), compute:
  - EV(Stand) = expected outcome vs dealer distribution
  - EV(Hit) = sum over next card p(c) * EV(next_state)
  - EV(Double) = 2 * sum p(c) * EV(stand_after_one_card_state)
  - EV(Split) = evaluate per split rules and recursion depth
  - EV(Surrender) = -0.5 (if allowed, and if not vs dealer blackjack restrictions)
Pick argmax EV.

Dealer distribution:
- Precompute P(dealer_final_total | upcard, rules) for H17/S17 and decks model.

### Approach B: Precomputed basic strategy tables
- Store strategy tables for common rulesets (e.g., 6D H17 DAS no-surr, 6D S17 DAS LS, etc.).
- Pros: fast.
- Cons: many combinations; easy to mismatch a machine’s exact rules.

**Use A for correctness; cache results** so the app is instant after first compute.

Wizard of Odds offers a basic strategy calculator by ruleset (useful for validation, not for copying tables verbatim). :contentReference[oaicite:2]{index=2}

## 6) Betting Strategy Module (Spice with strict caps)

### User selects a betting mode
- Flat bet
- Mini-Paroli (1-2-4, stop after 2 presses)
- Oscar’s Grind (target +1u per set, cap)
- Ladder cycle (user-defined sequence)
- Martingale-Lite (1→2 only, then reset)
- Custom: “sequence file” the user defines (e.g., JSON list)

### Hard safety rails (required in UI)
- Unit size (u)
- Max bet cap (e.g., 4u default)
- Session stop-loss (e.g., -25u)
- Session take-profit / “lock” (e.g., +10u)
- Optional: “cooldown” after X hands to slow pace

### State machine per strategy
Each strategy implements:
- `reset()`
- `nextBet(lastOutcome, bankroll, caps) -> bet`
- `onHandStart(bet)`
- `onHandEnd(outcome, delta)`

- session_id

- dealer_upcard

- recommended_action

- outcome
- payout_delta
- running_bankroll_after
- tags (double, split, surrender, blackjack)

### Export
- CSV export per session
- JSON export for replays
- “Session summary” screenshot-friendly view

## 8) Analytics & “Don’t Burn Wallet” Tools

### Expected loss/hour estimator
Inputs:
- avg bet, estimated hands/hour, house edge
Output:
- expected $/hour loss (and per 100 hands)

Electronic blackjack can be extremely fast (up to ~600 hands/hour heads-up), so controlling pace is a real lever. :contentReference[oaicite:3]{index=3}

### Mistake tracker
- Compare user action_taken vs recommended_action
- Show “EV cost” estimate (optional)

### Ruleset quality meter
- Highlight worst rules (esp. 6:5 and even-money blackjack)
- Show house edge estimate from the configured ruleset
Wizard of Odds documents how rule variations affect player return. :contentReference[oaicite:4]{index=4}

## 10) Tech Stack Recommendation

### Option 1: PWA (best for “in casino”)
- Frontend: React + TypeScript
- Storage: IndexedDB (Dexie.js)
- Engine: TypeScript module (pure functions), cached results
- Offline-first, add-to-home-screen, no app store friction

### Option 2: Native mobile (if you want max smoothness)
- Flutter or React Native
- Local SQLite
- Same engine ported/shared

- Unit tests: dealer distribution sums to 1; EV monotonic sanity checks
- Golden tests: known rulesets compared against an external calculator output for a sample of states (strategy action + house edge). :contentReference[oaicite:5]{index=5}
